# ADR-001：采集范围、热度和历史存储

日期：2026-10-30。状态：已采用。

使用 React/TypeScript + FastAPI + SQLAlchemy + MySQL 8.0。API 只负责读取，worker 独立采集，避免多个 Web 进程重复执行定时任务。

GitHub 没有“所有 Skills 项目的官方实时热度榜”。每轮按配置关键词各搜索累计 Star 和最近更新前 100 项，规则识别 Agent/Claude/Codex Skills。默认从搜索结果选累计 Star 与最近推送各 100 项，并持续观测最近识别的 200 项，合并后最多约 400 项。候选截断、搜索索引延迟与规则误判意味着不能保证覆盖全网前 20。通过详情提供识别依据；不足 20 项时如实显示。

累计榜按 Star 降序，增长榜按实测净增 Star 降序；平手按累计 Star、稳定 GitHub ID 排序。24h 基线选取观测时间前 24 小时及更早 2 小时窗口内最近快照，展示基线时间；缺失不参与增长排名，不回填历史，不把负增长归零。首日可以查看累计榜。

每个半小时窗口唯一批次。MySQL GET_LOCK 负责跨进程互斥，成功批次幂等。进程崩溃后连接释放锁，重启可恢复同一窗口 running/failed 批次；错过的窗口不伪造补采。网络抓取在事务外，快照和两个榜单一次提交，失败不污染上一期榜单。README 和名字跟随快照保存，使历史可复现。

UTC 存储，接口 ISO8601 UTC，前端统一北京时间。数据库初始化显式执行，现阶段建表命令只适合首次部署；后续修改结构必须增加迁移，不能依赖 create_all 更新旧表。

不渲染 README HTML，不执行仓库脚本，不跟随任意外部 URL，不向浏览器提供 GitHub Token 或数据库密码。读接口默认作为本机个人工具，公网部署须在反向代理加入认证和 TLS。
